# Worked mechanism decisions

These anonymized cases derive from the three August 2026 validation
decisions. They illustrate the decision layer; they do not validate a product,
prescribe a canonical form, or reproduce private source material.

| Decision | Narrow route | Selected mechanism | Rejected or deferred | Boundary and handoff result |
| --- | --- | --- | --- | --- |
| A solo delivery practice spans intake, research, delivery, and follow-up while a CRM already owns relationships | Client delivery + CRM operations | Existing CRM plus a manual checklist; add client-local ICM routing only if distinct artifacts repeat | A new workspace now; automation before repetition is demonstrated | CRM retains identity, stages, consent, tasks, and timestamps. A person approves scope, commitments, acceptance, and delivery. No Architect handoff. |
| A learner needs to navigate a large private educational corpus | Research and knowledge hub + learning-librarian example | Existing local router and adaptive learning path | Retrieval or persistent infrastructure before a navigation failure; a new ICM build | The course remains authoritative; synthesis is reviewed interpretation. Exact-file and destination clearance is required for hosted use. No Architect handoff. |
| Agents need to understand the impact of changes in a mixed repository | Repository/workspace change-impact pattern | Existing root router and source-citing map | A new inventory or map build before a real change-impact gap is demonstrated | The repository remains authoritative; maps cite it rather than becoming a second specification. Hand off only for an actual inventory, map build, restructure, or cold-walk audit. |

In each case, the decision stopped at the smallest sufficient mechanism. A
pattern supplied orientation and a boundary; neither preselected an ICM form.
