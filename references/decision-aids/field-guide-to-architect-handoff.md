# Field Guide-to-Architect handoff brief

Use this template only after the Field Guide has selected ICM (or an
ICM hybrid) **and** the user wants a workspace built, changed, or audited.
It carries orientation and boundaries forward; ICM Architect determines the
canonical form, structure, contracts, and walk test.

## Brief

```md

- Requested build, change, or audit:
- In-scope roots and explicit write authority:
- Out of scope:

- Smallest mechanism selected: ICM / hybrid
- Why a lower-complexity mechanism is insufficient:
- Repeating unit observed:
- Likely work movement or accumulation (hypothesis, not a form selection):
- Existing routers, artifacts, or systems to retain:

## Authority and operating boundaries
- Human approvals and decision artifacts:
- External systems that retain truth or action authority:
- Triggered boundaries: untrusted content / sensitive data / memory /
  consequential action / concurrency / automation / deployment / runtime /
  external dependencies
- Data or deployment limits:

## Discovery still needed
- Facts to verify before structure is proposed:
- Material uncertainty or assumptions:
- Explicitly rejected additions:
```

Do not fill in an Architect form name, folder skeleton, template, or migration
map here. If ICM is no longer the smallest mechanism, return to the Field Guide
decision instead of handing off.
