# External code and dependency assurance

- **Trigger:** a build, workflow, or map adopts an external repository,
  package, action, installer, or automation dependency.
- **ICM boundary:** folders can route evidence and decisions; they do not
  sandbox code, prove provenance, or establish supply-chain integrity.
- **Do not infer:** popularity, a polished README, or generated scores are not
  trust guarantees.
- **Human check:** approve adoption and execution with review depth proportional
  to failure cost and exposure.
- **Removal test:** do not impose a supply-chain review on local prose or an
  already-approved, unchanged runtime component beyond its normal controls.
