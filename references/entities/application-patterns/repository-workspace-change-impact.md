# Repository or workspace change-impact map

Use this pattern when the subject is an existing codebase, Markdown vault, or
mixed tree that later agents must edit safely. The repeating unit is an object
or change surface, not a feature-delivery run.

## Use it when

Use upstream's
[System Map](https://github.com/RinDig/icm-architect/blob/b20fb45063a564cf607b03526e206f519d174def/references/forms.md#6-system-map--a-body-of-work-as-an-edit-graph)
when a cold agent must learn what a noun is, how real processes move it, and
what an edit hits without loading the whole tree. If one small router and an
index already answer those questions, stop there.

## What it contains

- one catalog that routes into the map;
- source-citing object cards for live nouns;
- process cards only for movements that actually run;
- a change-impact index that points to cards rather than copying them; and
- explicit live, leftover, and ghost distinctions.

The subject tree remains authoritative. The map cites it and must not become a
second specification.

## Human boundary

Approve the inventory and proposed clusters before cards are written. Recheck
load-bearing citations and change waterfalls before calling a card verified.
Use ICM Architect for the inventory, target tree, migration, and cold walk.
